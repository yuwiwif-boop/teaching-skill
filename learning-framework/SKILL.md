# 学习总框架

建立一套以深层概念理解为目标的长期学习结构。理解不是拥有一组互不相连的事实，而是能从少量可靠基础重新推导结论；认知图谱用于保存这些认识及其生成关系。理想结果是学习者产生“压缩感”：原本零散的事实收束为少数生成性认识和清晰依赖。

认知图谱是一张稳定、可更新的总地图；节点必须代表可独立验证的生成性认识，而不是章节、术语、活动或操作步骤。

始终使用简体中文与用户交流和写文件；专有名词首次出现时可附原文。

## 启动边界

只在以下模式中工作：

1. 新工作区初始化。
2. 用户要求检查或修改现有图谱。
3. 教学抵达图谱边界，需要扩展新知识簇。
4. 使命、主路线或范围需要改变。

若请求只是继续学习、教授当前节点、验证掌握或组织复测，不执行本 Skill；改用 `$concept-teaching`。

## 结构原则

- 图谱只含认知节点。每个节点应能用“用户能够解释……为何发生，并据此处理……”来陈述。
- 依赖边表示可解释的生成关系：前置认识应参与推导后继认识，不能只表示教材先后、常见教学顺序或主题相邻。
- 优先寻找少量可靠基础，再把结论显式建立在其上；但不得为了形式整齐而强造基础节点。
- 严格区分“无条件真理”和“公理或根节点”：前者描述学习者能否不带保留地接受一个陈述，后者描述它在当前图谱中的位置。二者可能重合，但不是同义词。
- 真正无条件的陈述不能暗含“通常”“在多数情况下”等条件。若条件不可删，应把适用条件写明或继续向更基础处追溯。
- 前置关系必须是有向无环图（DAG）。现实反馈循环写入节点内容，不建立循环前置。
- 图谱有一个最终目标节点和少量阶段目标节点。所有关键节点都必须存在通往最终目标的路径。
- 节点分为“关键”和“辅助”；不能连接现实使命的内容不进入图谱。
- 每类字段各有唯一权威位置：状态表保存依赖、类型、知识簇与当前状态；`nodes/N-xxx.md` 保存完整节点定义；`nodes/C-xx-LEARNING.md` 保存该簇节点证据；`nodes/NOTEBOOK.md` 保存简短跨节点背景和结构事件；`MAP.md` 只是派生视图。
- 教材提供知识结构线索，但章节目录不等于学习路线。
- 采用“一本主教材定结构，多来源核验关键处”：关键定义、关键依赖和争议内容必须用独立权威来源核验。
- 权威来源有分歧时，记录适用条件与争议点；若会改变主路线，请用户选择框架。

## 新工作区初始化

按以下阶段推进；没有得到相应确认时停在当前阶段，不预先写入最终状态文件。

1. **使命契约**：明确现实目标、最终验证任务、范围、约束和范围外内容。一个工作区只服务一个连贯使命。
2. **教材候选**：调研并提出少量权威主教材候选，说明各自与使命的匹配点和取舍；请用户确认主教材。
3. **初始骨架**：从主教材提炼生成性认识，用独立来源核验关键节点和依赖，建立覆盖使命主路径的骨架。对每个候选根节点做压力测试：它是否只是伪装成基础事实的中层结论；若能从更简单、学习者更容易接受的认识推出，就继续下沉。暂不穷举遥远分支。
4. **简短筛查**：只筛查主路径及其直接前置，并简要确认候选基础陈述对用户是否真的坚实。自述经历或简单答题只能帮助选择起点；只有同时证明能解释原因、连接前置机制并解决新问题，才能标记已掌握。
5. **个性化草案**：展示使命、主路径、起点、节点与依赖、阶段目标和结构来源，请用户确认初始图谱。
6. **落盘**：确认后创建精简的 `LEARNER-STATE.md`、各 `nodes/N-xxx.md`、按簇的 `nodes/C-xx-LEARNING.md`、简短 `nodes/NOTEBOOK.md`、派生 `MAP.md` 与 `RESOURCES.md`。没有证据的簇可暂不建立证据文件；未充分验证的节点一律为“未掌握”，不写冗余占位证据。

不创建 `MISSION.md`、课程进度文件、学习记录目录、问题文件或中断恢复文件。

## 扩展或修改图谱

先读取精简状态表，仅按影响范围打开相关节点文件、分簇证据或笔记片段、资源和地图。用户已经明确指定具体修改时，可直接执行不改变主路线的局部修复；若会改变使命、主路线、范围或争议框架，必须先展示影响并取得确认。

只扩展即将进入的知识簇：先查证，再补图，再对新增区域做局部进度筛查。不要一次预建整个领域。

应用结构变化时：

- 未受影响节点文件、状态行和分簇证据保持原样。
- 新增、拆分、合并或陈述、判据、依赖被实质修改的节点设为“未掌握”。
- 受影响节点的下游不立即清零，但把复测标志设为适当的“到期”类别；结构原因简记于 `nodes/NOTEBOOK.md`。
- 删除节点不再出现在当前状态表；在 `nodes/NOTEBOOK.md` 的退役 ID 映射与结构事件中保存替代关系。
- 只迁移或失效受结构变化影响的数据，绝不覆盖无关教学数据。
- 相关笔记和 HTML 仅在受影响节点定义中标记“待复核”，不代替教学 Skill 重写。
- 每次结构提交只递增一次结构版本；普通状态变化不递增版本。
- 只新建或修改受影响的节点定义、状态行与 `MAP.md` 中受影响的视图，并向 `nodes/NOTEBOOK.md` 追加简短结构事件；需要迁移的证据只调整受影响簇。由状态表中的依赖重建边；未变化的视图不重写。

## 提交前一致性检查

至少确认：

- 状态表节点 ID 唯一；每行详情文件存在且 ID 对应；前置 ID、来源 ID 和阶段目标 ID 均存在。
- 前置图无环，最终目标唯一。
- 每条依赖都能回答“前置认识如何帮助发现或推出后继认识”；不能回答的边应删除或重新查证。
- 每个根节点都经过压力测试，没有把可继续推导的中层定理误称为公理；标为无条件的陈述在其写明范围内确实没有隐藏条件。
- 每个关键节点都能沿依赖方向到达最终目标；没有与使命无关的孤立节点。
- 稳定掌握判据可通过开放解释与迁移问题验证，也能构造无歧义的结课选择题；不以“读过、做过、记得术语”为判据。
- `MAP.md` 的节点、简称和边均可由状态表重建，不承载额外结构事实。
- 结构迁移遵守字段所有权；未受影响状态和分簇证据没有变化。
- 主教材、关键节点与关键依赖在 `RESOURCES.md` 中具有可追溯来源。

完成后简短报告：新结构版本、变更节点、保留或失效的数据、被提前的复测，以及是否仍需用户决定。不要自动开始教学。
